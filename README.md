# 閉域環境でのローカルLLM出力検収

通信を遮断したノートPC1台で、行政が公開しているガイドライン文書から
職員が守るべき事項を抽出し、その出力を原典の項目と自動で照合する。

## 何をするものか

- `run.py` … 文書の全文と設問を、手元で動くモデルに渡し、表を作らせる
- `check.py` … 出てきた表の各行を原典の項目と突き合わせ、
  当たった行・当たらなかった行・抜け落ちた項目・重複を出す

## 背景

同じ端末・同じモデル・同じ文書でも、アプリの画面から実行すると
文書の一部だけが渡され、重要な項目が抜け落ちることがある。
全文を自分で渡す形にすると、抜けはなくなった。

さらに、照合を書いた側にも誤りが出た。
最初の版は表記の違いを吸収できず、出力に存在する項目を
「現れなかった」と誤って報告した。
出力を確かめる仕組みそのものにも、確かめる工程が要る。

## 動作環境

- Windows 11 / Python 3.13（追加ライブラリなし。標準機能のみ）
- LM Studio 0.4.20 のローカルサーバー（http://127.0.0.1:1234）
- モデル：openai/gpt-oss-20b（GGUF・MXFP4・12.11GB）
- コンテキスト長 32768 / temperature 0
- メモリ16GBの端末でWSL経由のLinuxを使う場合、既定の割当は7.6GBとなり、本ツールが前提とする12.11GBのモデルは読み込めない。詳細は `measurements/` を参照

## 実行

1. LM Studioでモデルを読み込み、Developer → Start Server
2. 対象文書のテキストを `gl.txt` として同じ場所に置く
3. `python run.py` → 出力が `out.txt` に保存される
4. `python check.py` → 照合結果が表示される

## 実測

- 入力 8,343トークン / 出力 874トークン / 所要 81.54秒
- 出力10行に対し、原典の遵守事項6項目すべてが含まれていた（欠落0件）
- 実行はすべて機内モードで行った
